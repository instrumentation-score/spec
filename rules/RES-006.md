**Rule ID:** RES-006

**Description:** `service.criticality` uses the canonical form of its well-known values

**Rationale:** The `service.criticality` resource attribute indicates the operational importance level of a service. Using the standardized well-known values enables automated prioritization of alerts, incidents, and resource allocation decisions across heterogeneous environments. Case or whitespace variants of these values fail exact matching, so tooling cannot reliably compare or act on them. Defined in the [OpenTelemetry Semantic Conventions for Resources](https://opentelemetry.io/docs/specs/semconv/resource/service/).

**Target:** Resource

**Criteria:** If the `service.criticality` resource attribute is present and its value, after trimming whitespace and ignoring case, equals one of the well-known values `critical`, `high`, `medium`, or `low`, the value MUST be exactly that lowercase well-known value. Custom values that do not match a well-known value pass this rule.

**Examples:**

- "Resource attribute `service.criticality` is set to `HIGH` instead of the expected lowercase `high`."
- "Resource attribute `service.criticality` is set to `Critical` instead of the expected lowercase `critical`."

**Impact:** Normal
