**Rule ID:** MET-008

**Description:** Metrics do not contain sensitive data such as PII, financial identifiers, credentials, or health information.

**Rationale:** Telemetry data is typically stored in observability backends with broader access than production databases. When metrics contain sensitive data, it creates compliance risks (GDPR, HIPAA, PCI-DSS) and security vulnerabilities. Common leakage vectors include data point attributes capturing user identifiers or unsanitized URLs, exemplar attributes copied from spans, and metric names built dynamically from user input. OpenTelemetry Semantic Conventions [explicitly discourage](https://opentelemetry.io/docs/specs/semconv/general/attributes/#sensitive-information) recording sensitive information in telemetry attributes.

**Target:** Metric

**Criteria:** Metric data MUST NOT contain patterns that match common sensitive data formats, including but not limited to:

- Email addresses (e.g., `user@example.com`)
- Credit card numbers (13-19 digits, after removing spaces and hyphens, that pass Luhn validation)
- Social security numbers or national ID numbers (e.g., `123-45-6789`)
- Bearer tokens, API keys, or other credentials (e.g., `Bearer eyJ...`, `sk-...`, `AKIA...`)
- Passwords or secrets in key-value patterns (e.g., `password=...`, `secret=...`, `token=...`)
- Financial identifiers such as bank account numbers or tax IDs
- Health data in key-value patterns (e.g., `diagnosis=...`, `patient_id=...`, `insurance_id=...`)

This rule applies to every string and integer value in metric data (integers are matched in their decimal form), including values nested in array or map values:

- Metric names, descriptions, and units
- Data point attributes
- Exemplar attributes
- Instrumentation scope names, versions, and attributes

Keys are evaluated together with their values: a non-empty value under a key naming a sensitive field, such as `password`, `secret`, `token`, `api_key`, or `ssn`, matches regardless of its format.

Attributes such as `enduser.id` are excluded from pattern matching when their values are opaque, non-reversible identifiers.

**Examples:**

- "Metric `http.server.request.duration` has data point attribute `url.full` with value `https://api.example.com/reset?token=abc123`, which includes a credential."
- "Metric `login.failures` has data point attribute `user` with value `alice@example.com`, which includes an email address."
- "Metric named `orders.alice@example.com.count` includes an email address in its name."

**Impact:** Critical
